## 0 规则维护（最高优先，先于其他一切条款）

- 用户每指出一次问题，同一轮内必须做完三件事，缺一件就算没改：
  1. 在本文件增/改对应条款，给固定编号（R1…Rn），写清"看到什么算违规、怎么改"；
  2. 把新条款同步进项目指令（用户粘贴，或我改）；
  3. 回头扫已交付文件，列出同类的存量违规并修掉（改不动就列成待办，不装作不存在）。
- 只改产物、不写规则＝下次照原样再犯；只写规则、不回扫存量＝旧文件继续错。两种都不算完成。
- 每条规则必须可执行、可检查：形容词式的"更严谨""更通顺""注意逻辑"不收，要写成能判定的条件。
- 交付前必须跑一遍机械检查（`draft_audit.py`，见仓库根目录），再人工过第 4.4 节的 7 条自检；脚本报出的命中要逐条说明是真违规还是误报，不许省略。
- 规则与实际冲突时（用户改了口径、数据口径变了），先改规则再动产物，并记进文末"变更记录"。
- 用户说"你自己跑过没"这类话时，正确回应是跑一遍并报结果，不是保证"下次一定注意"。

## 4 工作纪律（写任何文档、方案、结论之前先服从本节）

### 4.1 事实：只写查得到的东西，不脑补

- 数据陈述只来自 `F:\Naruchit data\1_Data of published manuscripts\3_Hepatocyte differentiation` 里实际存在的文件；动笔前先列目录、打开关键文件（表格要看列名，图要看通道与命名），再写"现有/已有/现成/自带"。
- 说"现成管道/可直接复用"前，必须确认它的输入正好是你要喂的那类图；对不上就改成你能跑的做法。
- 不编造具体数字与结构：孔数、表型个数、Table 编号、样本量、门槛值，一律只能引用实际文件里有的东西。项目里不存在的（例如 Table 1、P1/P2/P3 三个表型）不许出现。
- 实验常识先过关再写：
  - 核分割与核形态特征提取只用 DAPI（后续为活细胞 Hoechst）的核通道，不用相差图；
  - 染色固定后细胞就死了，不存在"同一个孔从 Day 0 一路拍到 D17/D21"；现分析以 batch 为单位、同条件对齐即可；
  - 不要为显得严谨去发明孔级配对、姊妹孔、预注册 run 这类做不到的设计。
- 术语只用项目定义过的意思：表型 = 特征集合（GMM 无监督簇，不是细胞类型）；ALB/AFP = 分化/肝功能标志（不是 lineage marker）；OCT4/YAP = 解释指标（不是预测目标）。
- 不把本体系细节写成普适事实（例如"品质都在第 17–21 天用流式判断"），需要时写"在本体系中"。

### 4.2 不懂就问，不硬着头皮编

- 数据目录里查不到、涉及实验流程与可行性、涉及统计口径、或自己都觉得别扭的地方：先问，不写。宁可问一句，不要交一版错的。
- 提问一次问完（≤3 个、按依赖排序），不要边写边反复打断；问完等回复再动手。
- 用户已经给过的既定事实（数据根、1 条件 1 OIB、973 核数、991 弃用）直接沿用，不再猜、不再改口径。
- 用户说"不懂就问""先搞懂学理再写"时，先用自己的话复述要产出的东西与依据，得到确认再写。

### 4.3 先定体裁与范围，再动笔

- 先判体裁，三者不混：paper story（讲问题与论证链）/ proposal、future plan（用现有数据说怎么做）/ discussion（才写替代解释与机制边界）。
- paper story 里不写 discussion 的东西（"机制、关联、预测互不担保"这类三段论），也不写"要过三步""五环仅支持三句陈述"这类讲写作方法的旁白。
- 用户点名的节就是全部节：不自加"4.4 配对与判据""核心一环"这类自设章节；不自设 Table/Figure 编号顺序之外的结构。
- 只用用户指定的数据与现成图：图的形状可以复用，但组别、预期结果必须按新体系重写，对不上就重画，不许照搬旧组别。
- 不写没被要求的限定说明与免责句（如"本组 10 月数据只用于定表型词汇……"）；一句多余的话会让人怀疑整篇。
- 篇幅按用户指定优先级分配：预期结果/论证链为主，方法简单带过。

### 4.4 交付前的逻辑自检（硬闸，逐条过，过不了不许交付）

1. 每个结论有证据吗？每条观察有对应的图吗？没有就不写这条，或补图。
2. 有没有自相矛盾？（一边说"尚未分类"，一边说"某一类核"；一边说"不能配对"，一边写"同一孔键延续至终点"。）
3. 因果句说得清"谁导致谁"吗？说不清就删；确需保留，用一句"先 A 后 B 不等于 A 导致 B"点到为止，不展开、不引入无关解释。
4. 有没有车轱辘话与元话语？（"需要强调的是……""这句话的意思是……""推理的桥梁""仅支持三句陈述"）全删。
5. 术语都定义过吗？自造词（孔级表、构成量、表型轴、R² 增量、模型 A/B 的环节名）首次出现必须用人话解释一句，否则换成日常说法。
6. Objective 用陈述句，不用问句；标题不用问句。
7. 中英逐段对应吗？英文不许自行增删；英文半篇的图必须英文重画，禁止中文标注图共用。

### 4.5 表达

- 一段一个意思；Background / Hypothesis / Objective 每节不超过半页，报告会上没人读整页。
- 不口语化，也不堆抽象；图注要能被"傻瓜式"读懂，图里字越少越好。
- 交付说明先给结论与改动清单，不写"我正在……""让我先……"式自述，不把过程当成果报告。
- 用户说"简洁点"就真的删字，不要用小标题撑篇幅。

### 4.6 交付

- 交付件是可编辑 Word；PDF 只当预览，不当交付物（用户要在原文上改）。
- 改稿改原文，不另存散落版本；覆盖前确认目标文件就是当前版本。
- 参考文献给链接并逐条核验（Crossref 核标题/卷期页/作者），核不了的标"待核"，不编。
- "标红方便手动插入"= 正文里 author-year 引用位置标红，不是文献列表标红。
- 用词服从用户口径（如 paper → research），一次改全篇，不留半中半英的混用。

### 4.7 节奏

- 每轮先做 15 分钟量级的推想再动笔，宁慢勿急，宁可多推想。
- 一轮只推进用户点名的那件事，不顺手扩写别的章节。

### 4.8 计数、图与口径（2026-11-06 新增）

- 任何核数：只能取 `naruchit_pipeline\docs\counting_ledger.md` 里台账有的数（1573 原始 / 973 有效 / 991 旧口径弃用 / 2821 2D 切片核 / 868 匹配核）；台账里没有的数不许出现在正文、图注、PPT。
- 1573、973、991 是同一批 3D 视野的三种数核方式，只能选一个用；2821 不得称"细胞"；五个数不得相加、不得换算。
- 引用前先跑 `scripts\verify_count_ledger.py`，必须 PASS；新增口径先加台账行再更新脚本期望值。
- 改图前先回指"你要改的是〔图名〕的〔哪个问题〕"，确认后再动代码；用户贴的参照图只借风格，不改它本身。
- 图按 `docs\figure_style.md`：日期三色 #2166AC/#4DAF4A/#E8985E；森林图 effect=(median(HA)−median(no-HA))/IQR(no-HA)；每时间点一个点、不叠菱形；横线语义必须在图例写明；图注 ≤2 行；尺寸与 dpi 按规范，x 轴与内容重叠即不合格。
- 箱线图只用 QC 通过的核（`qc_pass_uniform == True`），不拿全检测直接画。
- 同一主题的图不许一夜出到第 6 版：改前先写 3 行规格（元素/颜色/尺寸），改完一次成型。

### 4.9 先读旧实现，再写新代码（2026-11-06 新增）

- 要画一张"复刻 Ekin"的图、或做一次"以前做过"的分割，先检索旧仓：森林图/箱线图/效应量、cellpose 2D 与 3D 入口都已有实现，读它、复算它，再决定改哪里。
- 不许因为"自己写更快"就重造；算出来和旧图对不上时，先查定义差异（特征、过滤、效应量），不要先怀疑数据。
